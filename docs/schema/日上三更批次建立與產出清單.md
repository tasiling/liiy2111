# 日上三更・批次建立與產出清單(委派書 v1.0,擁有者提供 sanko-batch-prototype.html,2026-08-03)

## 範圍與定位

依擁有者驗證過的 sanko-batch-prototype.html 原型實作,取代 /sanko 原本的「裸
明細編號清單」入口。解決委派書指出的三個問題:清單顯示識別碼難辨識、建立時
看不到日期範圍、每天只有一筆看不出晨光/日光/夜光。位置維持在聊解室→日上
三更(/sanko),不是新頁面——批次建立區與日期卡清單是這個頁面的新內容,原有
的生成流程(選方法→輸入牌→選光站→補充→產生指令→複製→貼回→標記完成)完全
沿用,不重新設計,只是入口從裸清單換成日期卡的「產出」按鈕。

## §4.2 引用的舊規格澄清(擁有者已確認)

委派書 §4.2 引用《日上三更生產引擎委派書 v1.0》第三章「拍照辨牌→選光站→選
方法→生成草稿→審核與輸出」,但實際上線的生成引擎是 /sanko 指令產生器(第二
份雛形定案的版本),流程是「選方法→輸入牌(文字)→選光站→補充→產生指令→
複製→貼回→標記完成」,沒有拍照辨牌這一步(技術驗證階段緩議,未實作)。擁有
者已確認:引用的是舊規格,不是現況,依實際上線的 /sanko 流程接,不臨時加拍照
功能。

## §五「更次的識別方式」裁決(方案 B,已執行)

委派書明確要求先評估三個方案再回報建議,不得自行實作。評估與裁決紀錄:

- **方案 A(明細編號末碼推導)否決**:若維持「一個 Session 涵蓋整個日期範圍」
  的既有批次語意,42 筆明細序號會是 01–42 連續遞增,不會依日期循環回
  01/02/03,末碼規則直接失效。要讓末碼規則成立,必須改成「一天一個
  Session」,這會把「一次批次建立」的動作在 Notion 紀錄層拆成 N 筆 Session
  記錄——擁有者裁決此舉是「紀錄層的語意損壞,比 schema 異動嚴重」,否決。
- **方案 C(借用「抽出順序」欄位)否決**:該欄位已被 /sanko 既有邏輯
  (`resolveCardsSection`)讀取為「抽出的牌卡識別碼序列」,混入更次標籤會弄
  髒既有用途,不安全。
- **方案 B(新增「更次」單選欄)採用**:語意明確,且維持「一個 Session 涵蓋
  整批」的既有資料形狀不變,序號正常遞增。擁有者已於 2026-08-03 在 Notion
  DB-04 新增「更次」單選欄(選項:晨光/日光/夜光),`lib/notion/schema.ts` 的
  `SANKO_UPDATE_TYPES` 對應這三個選項。

只有透過這次批次建立流程產生的明細會有「更次」值;既有/其他管道建立的明細
此欄留空,不是缺陷,單純代表「不屬於這個批次系統」,不強制回填。

## 資料模型

- 批次建立(`POST /api/sanko/batches`):建立 1 筆 DB-03 Session(項目用途=
  日更〔既有選項,無需新增〕,模式=批次)+ N×3 筆 DB-04 明細,序號 1..N*3
  正常遞增,每筆明細狀態=待產出,更次依序輪流寫入晨光/日光/夜光。用
  `runBatch`(既有的節流批次寫入工具)逐筆送出,回傳成功/失敗清單。
- 讀取(`GET /api/sanko/batches`):撈出所有「更次」有值的明細(不限狀態,
  已產出/已交付也要,才能算出每天 N/3 的完成度),前端依「所屬 Session」
  還原成一批一批,再依對應日期展開成日期卡,依更次分到三個欄位——分組是
  純展示邏輯,不在後端做。
- 快速勾選(`PATCH /api/sanko/batches/[id]/quick-toggle`):委派書 §4.4 明訂
  「取消勾選→待產出」是允許往回走的動作,這與明細狀態機既有的「只能往前
  推進」規則衝突(`canAdvanceDetailStatus`)。這裡刻意繞開那個限制,新增
  `setDetailQuickDone()`,只在 待產出/待審核 ⇄ 已產出 之間切換,不觸碰
  已交付(仍視為終局歷史紀錄,擋在 API 層)。這是唯一允許往回走的明細狀態
  異動路徑,僅限日期卡的勾選方塊使用,不影響其他地方(如 /sessions 的明細
  狀態推進)的單向限制。

## 舊的「待產出清單」與新的日期卡清單並存

`/api/sanko/pending`(舊的裸清單 API)已改為排除「更次」有值的明細,避免同一
筆明細在頁面上重複出現兩次(日期卡一次、舊清單一次)。舊清單維持原樣,只是
現在只顯示「不屬於這個批次系統」的其他待處理明細(例如之前不經批次建立、
單筆手動建立的日上三更明細)——沒有隱藏任何既有功能,只是避免視覺重複。
