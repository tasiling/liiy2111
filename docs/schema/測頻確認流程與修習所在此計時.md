# 測頻確認/編輯流程 + 修習所各項目「在此計時」(2026-08-03)

## 一、收光測頻加確定與編輯

### 現象與要求

原本頻率/強度的滑桿一動即寫入 `entries`(`onChange` 直接呼叫
`setEntryFreq`/`setEntryIntensity`),沒有確認/取消機制,已標記後也沒有收合
狀態,兩顆清除鈕永遠顯示。要求改成三態:

1. **未標記**:「標記頻率」「標記強度」兩顆入口按鈕。
2. **展開中**:滑桿＋數值輸入＋「確定」＋「取消」;清除鈕移到這個狀態內。
3. **已標記**:收合成單行標籤(既有的 `formatFreqIntensityLabel()` 格式,例
   「140・欲求 ・ 強度 5」)＋一顆「編輯」按鈕。

### 設計決定:頻率與強度共用一個編輯面板,不是兩個獨立狀態機

規格範例「140・欲求 ・ 強度 5」是**一行合併標籤**,只搭配**一顆**「編輯」按
鈕——不是各自獨立收合成兩行、各自一顆編輯鈕。若真的做成兩個完全獨立的
狀態機,「已標記」狀態要嘛得顯示兩行(跟範例的一行不符),要嘛就得決定
「只顯示已標記那個」而讓另一個未標記的欄位失去進入點。

因此改為:`ClosingMeasurePanel` 元件用**一個**共用的展開面板同時容納兩個滑
桿,「標記頻率」「標記強度」兩顆入口按鈕都打開同一個面板(差別只在使用者
是從哪個按鈕點進去,面板本身一視同仁顯示兩個欄位)。

### 避免「面板同時顯示兩個滑桿」誤觸未指定的欄位

若使用者只是想標記頻率,面板卻同時顯示強度滑桿(預設值 5),按下「確定」
時若無腦地把兩個欄位都寫回 `entries`,會在使用者根本沒動過強度滑桿的情況
下,把它從「未標記」變成「已標記(強度 5)」——違反既有的「只填其中一項
完全合法」規則。

解法:用 `touchedFreq`/`touchedIntensity` 兩個旗標追蹤這次編輯階段使用者是
否真的動過該欄位的滑桿或數字輸入(初始值取自「該欄位原本是否已有值」,若
原本已有值,不管有沒有再動過都視為已觸碰,重新送出同一個值視為正常行
為)。「確定」時只寫入 `touched` 為真的欄位,沒動過的維持原狀(不寫、不清
除)。

### 清除鈕

清除鈕(「清除頻率」/「清除強度」)只在該欄位**原本已有值**(`entry.freq
!= null`/`entry.intensity != null`)時才顯示在展開面板內,按下去立即呼叫
`setEntryFreq(id, null)`/`setEntryIntensity(id, null)` 並重置該欄位的暫存值
與 touched 旗標——不會等到按「確定」才生效(清除跟「確定」是兩個不同性質
的動作:清除是立即的、明確的移除意圖,不需要额外確認)。清除後面板仍停留
在展開狀態,不自動收合退出——避免使用者同時在調整另一個欄位、卻因為清除
了這個欄位而被強制關閉面板,平白丟失另一邊尚未確定的暫存值。

### 未按確定即離開,不寫入

「取消」直接把 `editing` 設回 `false`,暫存值(`pendingFreq`/
`pendingIntensity`)整個捨棄,不觸碰 `entries`——原本是什麼狀態,取消後就
還是什麼狀態。

## 二、修習所各項目直接計時

### 需求

修習所六個子項目(身／心的知情意／靈／光行／光法)的內容卡片上,各加一顆
「在此計時」,點擊後直接進入計時器,自動帶入場域、「你在練什麼」(子項目
名稱)、類型,以及有明確對應時的光行／光法預選——不能要求使用者到 /timer
再重新選一次自己剛剛所在的位置。

### 光行／光法的「明確對應」判斷

身、心的知/情/意、靈**沒有**任何規格文件建立過跟光行五/光法五的對應關
係——光行／光法是兩套完全獨立的選填標籤,不是身心靈底下的子分類(這是修
正委派書 v1.0 三就已經定案的架構)。若自行幫「知」配一個「煉光」之類的對
應,等於自行發明產品邏輯,委派書明確要求不得如此。因此這四個子項目一律維
持「不特別標記」(`guangxing`/`guangfa` 皆為 `null`)。

光行、光法兩個分頁本身則有明確對應:分頁裡目前選中的項目就是使用者要標記
的光行/光法值,直接帶入。

### 實作:`lib/dojo/store.tsx` 新增通用 `startTimerWith()`

原本 `startTimerWithGuangxing()`/`startTimerWithGuangfa()` 只服務光行/光法
兩個分頁,且各自寫死 `space: "practice"`。這次需要六個子項目共用同一種
「一次把完整 timerConfig 設好」的行為,把這兩個函式合併、通用化成:

```ts
export type StartTimerParams = {
  space: SpaceKey;
  title: string;
  kind: string;
  guangxing?: GuangxingKey | null;
  guangfa?: GuangfaKey | null;
};

startTimerWith(params: StartTimerParams): void;
```

跟既有的 `startTimerFromSpace()`(只帶場域,其餘沿用 `timerConfig` 上一次的
值,給 `DojoShell`/`ModuleDomainPage` 的通用頂部計時按鈕用)不同——
`startTimerWith()` 每次呼叫都是**完整覆蓋**整個 `timerConfig`,不合併舊
值,確保驗收要求的「不需要動任何選項就能按開始」。

`app/practice/page.tsx` 六個分頁各自呼叫:

| 分頁 | title | kind | guangxing/guangfa |
|---|---|---|---|
| 身 | `身` | `身` | 皆不設定 |
| 心・知/情/意 | `心・{sub}` | `心／{sub}` | 皆不設定 |
| 靈 | `靈` | `靈` | 皆不設定 |
| 光行(選中項) | `{名稱}:{第一個真實對應}` | `光行／{名稱}` | `guangxing` = 選中項 |
| 光法(選中項) | `{名稱}:{第一個真實對應}` | `光法／{名稱}` | `guangfa` = 選中項 |

光行/光法的 title 格式沿用前一輪已經設計好的 `${v[0]}:${v[2].split("、")[0]}`
(例:`煉光:閱讀`),沒有改動,只是改由新的通用函式承載。

## 三、計時器場域清單補齊道藏

`app/timer/page.tsx` 的 `TIMER_SPACE_KEYS` 原本用
`.filter((k) => k !== "closing" && k !== "dao")` 排除收光跟道藏。改成只排除
收光(收光是結束動作,不是投入時間的場域),道藏補回清單。

## 四、驗收

用 Playwright 走過:

- 修習所點「心」→「知」→「在此計時」→ `/timer` 頁面「你在練什麼」輸入框
  直接顯示「心・知」,場域選中「修習所」,光行/光法皆顯示「不特別標記」為
  選中狀態——不需要使用者手動調整任何選項就能按開始。
- 光行分頁選「煉光」→「在此計時」→ `/timer` 的「你在練什麼」顯示「煉光:
  閱讀」,場域選中「修習所」,光行選中「煉光」,光法維持「不特別標記」。
- `/timer` 的場域按鈕列包含「道藏」,不包含「收光」。
- 收光測頻:未標記時只有兩顆入口按鈕,無清除鈕;展開後拖動滑桿再按「取
  消」不寫入,重新整理狀態仍是未標記;展開後設定頻率＝140並按「確定」,收
  合顯示「140・欲求」＋「編輯」;點「編輯」重新展開且頻率預填 140、此時
  「清除頻率」按鈕出現;同時設定強度＝7 並確定,收合顯示「140・欲求 ・
  強度 7」;編輯後只按「清除強度」,收合／再次展開時確認頻率仍保留為
  140,強度回到未標記。
