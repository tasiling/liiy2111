# P8 方法系列組稿(空雨傘八法) 邏輯說明

對應擁有者指示(2026-08-01,語氣指引 v0.2 升版後追加):依語氣指引 v0.2 本文「六、
八方法版型與三段命名對照」表格,實作組稿台的方法系列生成套用。此表原任務描述稱
「整合規格書 v1.0 第五章 5.3 對照表」,經與擁有者確認後,直接以語氣指引 v0.2 頁面
內嵌表格作為權威來源(內容與八方法、空雨傘、傘型態完全吻合),不另尋獨立文件。

## 五項輸入

與 P8 階段一(`docs/schema/P8階段一組稿邏輯.md`)並列,但用途不同——階段一是抽牌解讀
主文,這裡是空雨傘八法日光互動貼文:

1. 牌卡資料:同階段一,`resolveCardsSection`。
2. DB-05 對應規則現行版:同階段一,`resolveRule`。
3. 語氣指引全文:同階段一,`resolveToneGuide`。「主文≤500 字+解析包」的輸出規格
   已隨全文(語氣指引第七章格式規範)一併帶入,不需要另外寫死。
4. 該方法的空雨傘三段命名與傘段型態:新增,`resolveMethodMapping`。
5. 輸出格式:同階段一,取自 DB-05 規則的「輸出格式」欄。

不含月主題包(DB-08)——此組稿情境不需要。

## 方法對照表解析(不寫死語氣規範於程式碼)

`lib/generate/methodTable.ts` 的 `parseMethodMappingTable()` 依欄位標題(方法/版型名/
空/雨/傘/傘型態)在語氣指引全文頁面的所有表格中比對,不寫死表格位置或列數。升版
(如 v0.2 → v0.3)只要表格欄位標題不變,方法新增/改名/傘型態調整都只是換 Notion
資料,完全不用動程式。

`GET /api/generate/methods` 回傳目前對照表的方法清單(版型名 + 傘型態),前端據此
動態渲染八個按鈕——按鈕文字本身也不寫死在元件裡。

## 語氣指引讀取規則的第三種情境(v0.2 起新增)

`resolveToneGuide()` 原本只處理兩種情境(內容=指標說明+連結有值→取回連結指向頁面
全文;或內容本身即全文)。v0.2 這筆「內容」「連結」皆為空,全文直接寫在本筆頁面
的內文區塊裡(本筆即單一本源)。新增第三種 fallback:兩者皆空時,依本筆頁面 ID
本身取回全文。三種情境不衝突,不需要判斷「是哪個版本」,純粹依資料形狀走對應
分支。

連帶修正 `fetchNotionPagePlainText()` 的一個既有 bug:table_row 區塊的文字放在
`table_row.cells`,不是一般區塊的 `rich_text`,原本的 walk 邏輯會靜默漏掉所有表格
內容(語氣指引 v0.2 本身有兩張表格)。已補上 table_row 專門處理,並新增
`fetchNotionPageTables()` 供需要結構化列/欄資料的場景(如方法對照表解析)使用。

## 生成品狀態(待審核)

依擁有者裁決:此狀態純粹是前端呈現的標籤,不寫入任何 Notion 資料庫(現有 16 個
資料庫都沒有存放「生成品」草稿+狀態的設計,新增資料庫需擁有者先在 Notion 端建好
欄位)。UI 上組出的提示詞一律顯示「生成品狀態:待審核」徽章,沒有任何按鈕可以
改變這個狀態或自動推進——狀態的實際變化(核可/退回)在生成品真的被寫入某個資料庫
之前,不是這次的範圍。

## 明細挑選邏輯共用

單篇組稿(`compose.ts`)與方法系列組稿(`composeMethod.ts`)都需要「決定要用哪一筆
明細」的邏輯(單筆 Session 自動取用;批次 Session 需指定 detailId),已抽出共用函式
`resolveDetailForSession()`(`lib/generate/sections.ts`),不重複寫兩份。
